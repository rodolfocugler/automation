# Home Automation

ESP32/ESP8266 firmware that lets Alexa control the TV, LED strips and lamps at home.
Alexa talks to Node-RED, Node-RED publishes to MQTT, and each ESP listens on its own topic
and sends IR or BLE commands to the device.

## Architecture

```
Alexa ──► Node-RED ──► Mosquitto (MQTT) ──► ESP32 ──► IR / BLE ──► TV, LEDs, lamp
              (all on the Raspberry Pi)        ▲
                                               └── OTA: polls nginx for new firmware
```

### Raspberry Pi (`pi-desktop`, 192.168.178.29)

| Service        | Address                   | Purpose                             |
|----------------|---------------------------|-------------------------------------|
| Node-RED       | http://pi-desktop:80      | Alexa integration, builds MQTT msgs |
| MQTT UI        | http://pi-desktop:81      | Broker admin                        |
| MQTT broker    | `pi-desktop:1883`         | Used by the ESPs                    |
| nginx (OTA)    | http://pi-desktop:9595    | Serves `/shared/ota`                |
| Jenkins        | http://pi-desktop:8080    | Builds and publishes firmware       |

SSH: `ssh jenkins-remote@pi-desktop`

| Room                 | Firmware              | Controls                 | How                          |

## MQTT contract

Each ESP is identified by `LOCALE` (room) and `ID`, set at the top of the `.ino`.

| Topic                        | Direction  | Notes |
|------------------------------|------------|-------|
| `alexa/<locale>/<id>`        | Pi → ESP   | Command for one device |
| `alexa/<locale>/all`         | Pi → ESP   | Command for every ESP in a room |
| `alexa/all`                  | Pi → ESP   | Command for every ESP |
| `device/<locale>/<id>`       | ESP → Pi   | Last processed message, **retained**. Read on boot to restore state |

### Payloads

LED / lamp:

```json
{
  "type": "led",
  "deviceName": "Led TV",
  "state": true,
  "rgb_color": [255, 0, 0],
  "brightness_pct": 80,
  "createdAt": 1760000000
}
```

`deviceName`: `Led TV`, `Led Cama`, `Luz Sala`.

TV:

```json
{
  "type": "tv",
  "action": "mediaControl",
  "value": "Netflix",
  "createdAt": 1760000000
}
```

`action` / `value`: `setPowerState` (`On`, `Off`), `mediaControl` (`Netflix`, `Youtube`, `Play`, `Pause`, `Ok`, `Exit`), `setMute`, `setVolume`.

### Message handling rules

- `createdAt` is a Unix timestamp (seconds) and is required.
- Messages older than **30 s** are dropped (ESP time comes from NTP, timezone `Europe/Berlin`).
- A message with the same `createdAt` as the last processed one is dropped.
- Bursts are debounced: only the last message within 200 ms is processed.
- Nothing is processed until the retained `device/<locale>/<id>` state has been read.
- The ESP restarts every 30 min and whenever Wi-Fi drops.
- The onboard LED stays off between 22:00 and 09:00.

## Deployment (CI/CD + OTA)

Push to `main` → Jenkins on the Pi runs one job per device:

1. `scp` the device folder (e.g. `production/sala/001`) to `~/build` on the Pi.
2. `arduino-cli compile` with the board's FQBN:
   - ESP32: `esp32:esp32:esp32`
   - ESP8266: `esp8266:esp8266:generic`
3. Copy the `.bin` to `/shared/ota/<chip>/<locale>/<id>/firmware.bin`.
4. Write `latest.json` next to it:
   ```json
   { "version": "20260602_214237", "file": "firmware.bin" }
   ```

nginx serves `/shared/ota` on port 9595. Every 30 s each ESP fetches
`http://pi-desktop:9595/<chip>/<locale>/<id>/latest.json` and, if `version` differs from its
`CURRENT_VERSION`, downloads and flashes `firmware.bin`.

> **Important:** a new ESP must first be flashed over USB with `ota/ota.ino`. Only after that
> will it start pulling new firmware via OTA (see [Adding a new device](#adding-a-new-device), step 4).

> **Note:** the build version is a timestamp generated by Jenkins, but `CURRENT_VERSION` is
> hardcoded in the sketch. If they don't match, the ESP will re-flash on every check. Keep them
> in sync (or inject the version at compile time with
> `--build-property "compiler.cpp.extra_flags=-DCURRENT_VERSION=\"$VERSION\""`).

## Adding a new device

1. Copy an existing folder to `production/<room>/<id>/` and set `LOCALE` and `ID`.
2. Create the OTA folder on the Pi: `mkdir -p /shared/ota/<chip>/<room>/<id>`.
3. Duplicate a Jenkins job, changing the source folder, `OTA_DIR` and `--fqbn`.
4. Set `LOCALE`/`ID` in `ota/ota.ino` and flash it over USB. It pulls the latest
   `production/<room>/<id>` build from the Pi and replaces itself (retries every 30 s).
   ```bash
   arduino-cli compile --fqbn esp8266:esp8266:generic --build-property "compiler.cpp.extra_flags=-DLOCALE=\"quarto\" -DID=\"001\"" ota
   ```
5. On first boot, join the `ESP-Config` Wi-Fi access point to configure Wi-Fi (WiFiManager).
6. Add the device in Node-RED, publishing to `alexa/<room>/<id>`.

## Local build

Requires [arduino-cli](https://arduino.github.io/arduino-cli/) with the `esp32` / `esp8266` cores and these libraries:
WiFiManager, PubSubClient, ArduinoJson (v6), IRremoteESP8266 (`001`), IRremote (`002`), NimBLE-Arduino.

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 production/sala/001
arduino-cli upload  --fqbn esp32:esp32:esp32 -p COM3 production/sala/001
```
